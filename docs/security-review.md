# Module 5 Security Review

This review grades the supplied AI findings against the current repository. The
proposed grades are advisory; the student retains the final decision.

| Finding ID | Severity | grade | Reason | Evidence needed or evidence used | Student decision |
|---|---|---|---|---|---|
| SEC-01 | Medium | Valid | `description` and `assignee` accept arbitrary-length strings on both create and update paths, while all matching tasks are materialized and returned without a limit. This is a credible availability/resource-use limitation outside the small in-memory course setting. | Verified in `app/models.py`: only `title` has a validator and 200-character cap. Verified `storage.get_all_tasks()` returns the full matching list; `GET /tasks` exposes no pagination parameters. |  the API is expected to remain local/small-data only. accepted course-scope limitation; And should add limits and pagination. |
| SEC-02 | Medium* | inValid | The API has no authentication or task ownership checks, so any reachable caller can read, create, modify, or delete tasks. The repository explicitly makes this an intentional course constraint, so it is not an implementation defect within the assignment, but remains a production deployment risk. | Verified all CRUD handlers in `app/main.py` lack identity/authorization logic. `app/CLAUDE.md` explicitly says not to add authentication. | Since it is learning local/course-only makes the limitation accepted;|
| SEC-03 | Low | inValid | This is accurately framed as a deployment-configurability limitation, not permissive CORS. The fixed localhost origins and HTTP API URL prevent normal non-local deployment and would need environment-specific configuration and HTTPS. | Verified `app/main.py` permits only the two local Live Server origins. Verified `frontend/index.html` sets `baseUrl` to `http://localhost:8000`. | non-local deployment is not in scope. accept as course-only configuration;  |
